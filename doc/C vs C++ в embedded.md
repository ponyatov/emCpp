# C vs C++ в embedded

Ранние embedded-системы характеризовались крайне ограниченными ресурсами: килобайты памяти, мегагерцы тактовой частоты. В таких условиях даже компилятор C++ мог генерировать избыточный код. Современные микроконтроллеры, даже бюджетные модели, обладают десятками или сотнями килобайт RAM и мегабайтами Flash-памяти, тактовыми частотами в сотни мегагерц.

Эволюция аппаратного обеспечения позволила перенести фокус с исключительной экономии ресурсов на баланс между эффективностью и сопровождаемостью кода. Крупные embedded-проекты, содержащие сотни тысяч строк кода, требуют современных подходов к организации программного обеспечения, которые предоставляет C++.

## развенчивание мифов

1. C++ всегда генерирует раздутый код

Это утверждение было справедливо для ранних реализаций C++, но современные компиляторы (GCC, Clang) демонстрируют исключительную эффективность. Такие возможности как шаблоны, inline-функции и constexpr вычисления позволяют перенести многие вычисления на этап компиляции, уменьшая размер исполняемого кода и повышая производительность.

2. Исключения и RTTI неприемлемы в embedded

Действительно, механизмы исключений и динамической идентификации типов могут вносить значительные накладные расходы. Однако современный C++ предлагает альтернативы:
- обработка ошибок через std::expected (C++23),
- типобезопасные объединения через std::variant,
- полиморфизм без RTTI через CRTP (Curiously Recurring Template Pattern).

3. STL слишком тяжёл для embedded

Хотя полная реализация STL может быть избыточна для некоторых embedded-систем, многие компоненты (алгоритмы, итераторы, умные указатели) могут использоваться изолированно. Кроме того, существуют embedded-ориентированные реализации стандартной библиотеки, такие как embedded STL (ESTL) или различные специализированные контейнеры.

## Когда C++ не подходит?

Несмотря на все преимущества, существуют сценарии, где C остается предпочтительным выбором:

- Системы с экстремально ограниченными ресурсами (менее 16KB RAM)
- Проекты, требующие сертификации по стандартам, где инструменты верификации лучше поддерживают C
- Команды, не имеющие опыта в современном C++
- Проекты, сильно зависящие от legacy-кода на C
